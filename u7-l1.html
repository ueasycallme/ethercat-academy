诊断工具箱

把 IgH 的 ethercat 命令和 Wireshark 过滤器按"它看的是哪一层"排好，出问题时先选对工具，再读对数字。

定位

本课目标

  1. 会用 ethercat CLI 的 12 个常用命令，并说出每条命令读的是主站缓存、ESC 寄存器还是从站对象字典。
  2. 会写 Wireshark 显示过滤器，按命令、地址、WKC 筛出想看的数据报。
  3. 会用三处读数（ESM 状态、域 WKC、6041）判断故障在哪一层。

    ethercat CLI 命令对照

    ethercat 是 IgH 主站自带的命令行工具，通过 /dev/EtherCATx 的 ioctl 向内核主站模块提问。它从不自己发帧：寄存器读写、SDO 都排进主站状态机，由主站在空闲时插进总线。下表以 IgH 1.5/1.6 为准，-p 选从站位置，-m 选主站号，示例输出为示意，字段以你手上版本的 ethercat <命令> --help 为准。

    命令作用看哪一层示例输出（示意）
    master主站阶段、网卡链路、收发帧计数、丢帧主站栈、网卡Phase: Operation Link: UP Lost frames: 0
    slaves [-v]列出从站：位置、别名、ESM 状态、错误标志；-v 显示 ID、端口、DCESM（主站扫描缓存）0 0:0 OP + Servo Drive
    states -p0 OP请求从站进入 INIT/PREOP/BOOT/SAFEOP/OPESM（写 AL Control）（无输出，再看 slaves）
    upload -p0 IDX SUBSDO 上传，读对象字典；可加 --type uint16邮箱 · CoE0x0237 567
    download -p0 IDX SUB VSDO 下载，写对象字典邮箱 · CoE（成功无输出，失败打印 abort）
    sdos -p0列出从站对象字典（需从站支持 SDO 信息服务）邮箱 · CoESDO 0x6041, "Statusword"
    pdos -p0SM 与 PDO 分配、映射项PDO 映射SM2: PhysAddr 0x1100 … RxPDO 0x1600 PDO entry 0x6040:00, 16 bit

    foe_read / foe_write经 FoE 读写文件，常用于 BOOT 状态下升级固件邮箱 · FoE（文件内容）
    debug N设置主站内核日志等级，输出进 dmesg主站栈（无输出，看 dmesg）
    graph以 Graphviz dot 格式输出拓扑拓扑、端口digraph bus { … }

    Wireshark：抓哪里、怎么过滤

    EtherCAT 帧的 EtherType 是 0x88A4，Wireshark 自带 ecat 解析器会逐个展开数据报。IgH 原生网卡驱动会把网卡从 Linux 协议栈拿走，此时在主站本机抓包通常看不到帧；用 generic 驱动，或在网线中间接交换机镜像口或 TAP。下表字段名取自 Wireshark 的 ecat 解析器，不同版本可能有出入，最稳的做法是在包详情里右键字段选"作为过滤器应用"。

    过滤器筛出什么对应课
    eth.type == 0x88a4所有 EtherCAT 帧（不依赖解析器）u1-l2
    ecatecat 解析器识别出的所有帧u1-l2
    ecat.cmd == 12命令码为 LRW 的数据报（周期过程数据）u1-l3
    ecat.cmd == 4 && ecat.ado == 0x0130FPRD 读 AL Status 的数据报u2-l1
    ecat.adp == 0x03e9地址字段 ADP 为某值（站地址寻址时即站地址）u1-l3
    ecat.cnt == 0WKC 为 0 的数据报：没有任何从站处理它u1-l3

    在主站网卡上，同一帧会出现两次：发出时 WKC 为 0，返回时 WKC 已被从站累加。比较这两次，就能看出哪一个数据报少了从站的应答。

    三处读数定层

    任何现象先读三个数：ESM 状态、域 WKC、6041。它们分别属于总线状态机、过程数据通路和驱动器状态机，从左到右依次排除。

    ESC 诊断寄存器含义读法
    0x0110DL Status：bit4–7 端口 0–3 物理链路，bit8–15 各端口回环/通信reg_read -p0 0x0110 2
    0x0130 / 0x0134AL Status（bit0–3 状态、bit4 错误）/ AL Status Codereg_read -p0 0x0130 2
    0x0300–0x0307各端口 RX 错误计数（无效帧、物理层错误）reg_read -p0 0x0300 8
    0x0310–0x0313各端口丢链计数reg_read -p0 0x0310 4
    0x0440SM 看门狗状态（过程数据看门狗）reg_read -p0 0x0440 2
    0x092CDC 系统时间差（本地与参考时钟之差）reg_read -p0 0x092C 4

    主从对照

    主站做什么

    • CLI 通过 ioctl 把请求交给主站模块；slaves、config、domains 读的是主站内存里的缓存与计数。
    • reg_read、upload、states 被排进主站状态机，在周期帧之外另发数据报，应用运行中也能用。
    • 主站记录丢帧数、每个域的 WKC 当前/期望值，并把详细日志写进 dmesg（用 ethercat debug 调级别）。
    • Wireshark 只看到线上的帧，看不到主站内部状态；两者要对照着看。

    从站做什么

    • 寄存器读写由 ESC 硬件在帧经过时应答，不需要固件参与，所以固件死机时 reg_read 仍能读到 0x0130。
    • SDO 要固件从 SM0 取请求、查对象字典、写 SM1 应答；固件忙或卡住就表现为超时。
    • 状态切换由固件检查配置后把新状态写进 0x0130，失败就置 bit4 并在 0x0134 写原因码。
    • ESC 自己统计端口错误和丢链次数（0x0300 起），这是查网线和接头的第一手证据。

    在真机上看

    按"主站 → ESM → 通路 → 驱动器"的顺序跑一遍，每条都和期望值对照：

    ethercat master                      # 主站阶段与丢帧
ethercat slaves -v                   # 每台从站 ID、状态、端口、DC
ethercat reg_read -p0 0x0130 2       # AL Status
ethercat reg_read -p0 0x0134 2       # AL Status Code
ethercat domains                     # WKC 当前/期望
ethercat upload -p0 --type uint16 0x6041 0
ethercat pdos -p0
ethercat reg_read -p0 0x0300 8       # 端口 RX 错误计数
    # Wireshark（抓镜像口或 generic 驱动网卡）
eth.type == 0x88a4
ecat.cmd == 12
ecat.cnt == 0
    读数期望值说明
    master: PhaseOperation应用已 activate；Idle 表示没有应用程序占用主站
    master: Lost frames0 且不增长增长说明帧没回来：网线、网卡或实时性
    slaves全部 OP 且为 +E 表示该从站置了 AL 错误位
    0x01300x08 0x00低 4 位 8 = OP，bit4 = 0 无错
    0x01340x00 0x00无 AL 错误码
    domains: WorkingCounter当前 = 期望IgH 期望值：每台有输出 +2，有输入 +1。此规则针对同时含输入输出的域（LRW）；纯输出域 IgH 改用 LWR，每台只加 1；纯输入域用 LRD，每台加 1。
    0x6041低位匹配 0x0027（掩码 0x006F）Operation Enabled
    0x0300–0x0307全 0 或长期不增长持续增长查网线、屏蔽、接头
    Wireshark ecat.cnt == 0周期 LRW 不应出现出现说明整段逻辑地址没有从站处理

    自测

    误区与关联

    • 误区：ethercat states -p0 OP 之后驱动器就能转了。
      实际上：这只切换总线状态机 ESM；驱动器还要靠 6040 走 CiA402 状态机到 Operation Enabled，而且没有应用程序周期发帧，从站很快会因看门狗退出 OP。
    • 误区：用 reg_write 或 sii_write 快速"修好"从站。
      实际上：这两条命令绕过主站状态机直接改硬件或身份信息，主站缓存不会同步；只在明确知道后果时使用，改 SII 前先 sii_read 备份。
    • 误区：ethercat slaves 的状态就是此刻线上的状态。
      实际上：它显示主站状态机最近一次读到的值；快速变化的故障要配合 reg_read 或 Wireshark 看。

    关联：WKC 规则见 u1-l3，AL 状态码见 u3-l1，SDO abort code 见 u3-l2，6041 解码见 u5-l1。下一课把这些工具串成决策树。

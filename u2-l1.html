ESC 内存映射与关键寄存器

在主站看来，从站芯片 ESC 就是一张按地址编号的内存地图：0x0000–0x0FFF 是寄存器，0x1000 起是过程数据 RAM。主站发出的每一条读写命令，最后都落在这张图的某个地址上。

定位

本课目标

  1. 说出寄存器区（0x0000–0x0FFF）和过程数据 RAM（0x1000 起）的边界，知道 RAM 大小从哪个寄存器读。
  2. 列出最常用的十个寄存器，说出各自由谁来写、拿来做什么。
  3. 逐位解释 AL Control（0x0120）和 AL Status（0x0130），会看错误位。

    机制拆解

    一块地址空间，两个访问入口

    ESC 的物理地址是 16 位，主站用 APRD/FPRD 等命令按这个地址访问，从站 MCU 经 PDI（SPI、并行总线等）访问同一张图。寄存器行为由 ESC 硬件实现，不需要固件参与应答；但有些寄存器只允许一侧写，例如 AL Status 由 PDI 侧写、主站只读。0x1000 以上是普通 RAM，由 SM 规定哪一段做邮箱、哪一段做过程数据。

    地址范围内容主要使用者
    0x0000–0x000F信息：类型、版本、FMMU/SM 数、RAM 大小、端口描述主站扫描时读
    0x0010–0x0013站地址、站别名主站写站地址
    0x0100–0x0111DL 控制与 DL 状态（端口、链路、回环）主站诊断拓扑
    0x0120–0x0135AL Control、AL Status、AL Status CodeESM 状态机（u3-l1）
    0x0200–0x0313事件屏蔽与请求、错误计数器中断、链路质量诊断
    0x0400–0x0443看门狗分频、时间、状态过程数据安全（u2-l2）
    0x0500–0x050FEEPROM（SII）接口读从站身份（u2-l4）
    0x0600–0x06FFFMMU，每个 16 字节逻辑寻址（u2-l3）
    0x0800–0x087FSM，每个 8 字节邮箱与过程数据缓冲（u2-l2）
    0x0900–0x09FF分布式时钟同步（u4-l1）
    0x1000–过程数据 RAM，大小见 0x0006（单位 KB）SM 缓冲所在地

    AL Control 与 AL Status 逐位

    两个寄存器的低 4 位都是状态编码：1 INIT、2 PREOP、3 BOOT、4 SAFEOP、8 OP。0x0120 的 bit4 是"错误确认"，0x0130 的 bit4 是"错误指示"。从站出错时把 0x0130 bit4 置 1 并在 0x0134 写原因码，主站在 0x0120 里带上 bit4 写一次才算确认。

    试一试：输入一个 0x0130 读数，看它被拆成哪些位。

    主从对照

    主站做什么

    • 扫描：广播读（BRD）0x0000，WKC 就是在线从站数。
    • 用自增寻址（APWR）给每台写 0x0010 站地址，此后都用 FPRD/FPWR。
    • 读 0x0000–0x0007 了解每台 ESC 有几个 FMMU、几个 SM、多大 RAM。
    • 写 0x0120 请求状态，再轮询 0x0130；不一致时读 0x0134 取原因。
    • 写 0x0600、0x0800、0x0900 区完成 FMMU、SM、DC 配置。

    从站做什么

    • ESC 硬件在帧经过时直接应答寄存器读写，固件不参与。
    • 上电时 ESC 从 EEPROM 装载 PDI 配置和站别名（0x0012）。
    • 固件经 PDI 收到 AL Control 事件，检查条件后写 0x0130；失败则置 bit4 并写 0x0134。
    • 固件只通过 SM 读写 0x1000 以上的 RAM，不关心帧里的地址。
    • ESC 自己累加 0x0300 错误计数、维护 0x0440 看门狗状态。

    在真机上看

    IgH 的 reg_read 直接对某台从站发 FPRD，输出按字节列出，低字节在前。

    ethercat reg_read -p0 0x0130 2    # AL Status
ethercat reg_read -p0 0x0134 2    # AL Status Code
ethercat reg_read -p0 0x0120 2    # AL Control（主站最近一次请求）
ethercat reg_read -p0 0x0000 8    # 信息区：类型、版本、FMMU/SM 数、RAM、端口
ethercat reg_read -p0 0x0010 2    # 站地址
ethercat reg_read -p0 0x0300 8    # 端口 0–3 的 RX 错误计数
    读数期望值说明
    0x01300x08 0x00OP、无错误；PREOP 时为 0x02，SAFEOP 为 0x04
    0x01300x14 0x00SAFEOP 且错误位置 1，接着读 0x0134
    0x01340x00 0x00无错误；非零时查 AL 状态码表（u3-l1）
    0x0000 第 0 字节ET1100 为 0x11其他芯片的类型值见各自手册
    0x0000 第 4、5 字节FMMU 数、SM 数ET1100 为 8、8；LAN9252 为 3、4
    0x0000 第 6 字节RAM KB 数ET1100 为 0x08，LAN9252 为 0x04
    0x0010非 0应与 ethercat slaves -v 里的站地址一致
    0x0300全 0 或长期不涨持续增长说明该端口网线或接头有问题

    自测

    误区与关联

    • 误区：0x0120 和 0x0130 是同一个寄存器的写和读两面。
      实际上：它们是两个寄存器。0x0120 是主站的请求，0x0130 是从站的实际状态；两者长期不一致，说明从站拒绝了转换或还没完成。
    • 误区：所有从站的过程数据 RAM 都是 0x1000–0x2FFF。
      实际上：RAM 大小因芯片而异，ET1100 8 KB、LAN9252 4 KB，以 0x0006 的读数为准；SM 配到 RAM 之外的地址通常会被从站拒绝。
    • 误区：寄存器是从站固件用软件模拟出来的。
      实际上：寄存器由 ESC 硬件实现，帧经过时立即应答。固件只经 PDI 访问同一张地图，所以固件死机时主站仍能读到 0x0000，却看到 0x0130 不再变化。

    关联：地图上 0x0800 那一块决定了 RAM 里哪段是邮箱、哪段是过程数据，下一课逐字节拆开 SM。

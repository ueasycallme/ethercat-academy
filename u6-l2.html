从站固件：协议栈与中断

ESC 硬件只负责收发和缓冲；从站 MCU 上的协议栈决定何时换状态、怎么回 SDO、何时拷过程数据。本课以倍福 SSC（Slave Stack Code）为样本，把固件拆成三层、一个主循环和两个中断。

定位

本课目标

  1. 画出 SSC 三层：ESC 驱动层、协议层、应用层，并说出各层的典型文件。
  2. 说出 MainLoop、PDI 中断、SYNC0 中断各做什么，以及 ESM 状态转换对应的 APPL_ 回调。
  3. 解释对象字典表如何把索引 6040 连到一个 C 变量，并列出自研协议栈的必备最小集。

    机制拆解

    SSC 三层

    SSC 把固件切成三层：最底层只会读写 ESC 地址，中间层实现 EtherCAT 协议，最上层是你的应用。你通常只改最底层（适配 MCU 与 PDI）和最上层（APPL_ 函数），中间层由 SSC Tool 按配置生成。

    层典型文件（以 SSC 版本与芯片为准）职责
    ESC 驱动层（硬件抽象）芯片相关的 *hw.c，如 el9800hw.c；LAN9252 由 Microchip 提供对应 HALHW_Init、HW_EscRead/HW_EscWrite、读 AL 事件寄存器、开关中断；PDI 可以是 SPI、并行总线或片上（如 ESC 集成在 MCU 内）
    协议层ecatslv.c、mailbox.c、coeappl.c、sdoserv.c、objdef.c、ecatappl.cESM 转换与检查（SM 配置、同步类型）、邮箱收发、CoE SDO 服务、对象字典、过程数据拷贝、看门狗处理
    应用层SSC Tool 生成的 <工程名>.c 及对象定义头文件APPL_* 回调：状态转换钩子、输入输出映射、控制算法

    一个主循环、两个中断、一个定时器

    SSC 可以全轮询，也可以用中断；实时从站一般打开 PDI 中断和 SYNC0 中断，邮箱这类不紧急的事留给主循环。谁拷输出、谁调应用，取决于 1C32/1C33 的同步类型（Free-run、SM 同步、DC SYNC0，见 u4-l2）。

    上下文触发做什么
    MainLoopmain() 里无限循环处理 AL Control 事件（状态转换）、邮箱收发与 SDO；未开中断时也在这里轮询过程数据
    PDI_IsrESC 的 PDI 中断（AL 事件，如 SM2 被写）SM2 事件时调 PDO_OutputMapping → APPL_OutputMapping 取走输出；SM 同步模式下还接着调应用与输入拷贝
    Sync0_IsrESC 的 SYNC0 引脚DC 同步模式下调 APPL_Application 与 PDO_InputMapping → APPL_InputMapping，把新输入放进 SM3
    ECAT_CheckTimer约 1 ms 的定时器LED、状态转换超时、看门狗检查等计时类工作（具体内容以 SSC 版本为准）

    ESM 回调

    协议层在每次状态转换时先做规范要求的检查，再调对应的 APPL_ 回调。回调返回 0（ALSTATUSCODE_NOERROR）表示同意；返回一个 AL 状态码则转换失败，协议层把该码写进 0x0134 并置 0x0130 的错误位。

    转换回调应用在里面做什么
    INIT → PREOPAPPL_StartMailboxHandler准备邮箱相关资源
    PREOP → INITAPPL_StopMailboxHandler释放邮箱相关资源
    PREOP → SAFEOPAPPL_StartInputHandler检查映射与同步设置，开始采集输入（6041/6064 开始有效）
    SAFEOP → PREOPAPPL_StopInputHandler停止输入更新
    SAFEOP → OPAPPL_StartOutputHandler允许输出生效，此后 6040/607A 才被执行
    OP → SAFEOPAPPL_StopOutputHandler输出置安全值（如禁止使能、停车）

    此外还有 APPL_GenerateMapping（按 1C12/1C13 算出输入输出长度）和 APPL_AckErrorInd（主站确认错误时调用）；这两个名字与签名以 SSC 版本为准。

    对象字典表与自研最小集

    SSC 的对象字典是一张由 SSC Tool 从 Excel 或 ESI 生成的静态表：每行给出索引、名称、各子索引的数据类型/位长/访问权限，以及一个指向 C 变量的指针。SDO 读 6041 时，CoE 服务查表找到指针，把变量内容拷进应答；PDO 映射到 6040 时，输出拷贝直接写这个变量。

    索引名称类型 / 位长访问指向的变量（示意）
    0x6040ControlwordUNSIGNED16 / 16RW，可映射 RxPDOObj0x6040
    0x6041StatuswordUNSIGNED16 / 16RO，可映射 TxPDOObj0x6041
    0x607ATarget positionINTEGER32 / 32RW，可映射 RxPDOObj0x607A
    0x1C12SM2 PDO 分配数组，子索引 0 为个数RW（PREOP）sRxPDOassign

    表的结构体名（如 TOBJECT）和变量名是 SSC Tool 的生成约定，以 SSC 版本为准。不用 SSC 自己写协议栈时，下面是能通过主站配置、进 OP 并稳定运行的必备最小集。

    必备项对应规范机制
    ESM：响应 0x0120，更新 0x0130/0x0134，支持错误确认u3-l1
    转换检查：SM0–SM3 配置、同步类型与 1C32/1C33 是否合法u2-l2、u4-l2
    邮箱 + CoE SDO 上传/下载（至少快速传输），含 abort codeu3-l2
    对象字典：1000、1018、1C00、1C12、1C13、1600/1A00 及应用对象u3-l3
    过程数据拷贝：SM2 → 变量，变量 → SM3u3-l3
    看门狗到期处理：输出置安全值、退回 SAFEOP 报 0x001Bu2-l2
    SII 内容与 ESI 一致（厂商号、产品号、邮箱与 SM 默认值）u2-l4

    主从对照

    主站做什么

    • 写 0x0120 请求状态，然后轮询 0x0130，直到到达或出现错误位。
    • 在 PREOP 通过邮箱写 SDO（1C12/1C13、映射、6060 等）。
    • SAFEOP 前配好 SM2/SM3、FMMU、DC；OP 后每周期发一帧 LRW。
    • 看到错误位时读 0x0134，写 0x0120 的 bit4 确认。

    从站固件做什么

    • ESM 读到 0x0120 变化，做检查并调 APPL_Start/Stop 回调，结果写 0x0130/0x0134。
    • MainLoop 取 SM0 邮箱，CoE 查对象字典应答，写入 SM1。
    • PDI_Isr 拷输出，Sync0_Isr 跑控制周期并拷输入。
    • 输出 SM 看门狗到期：停输出，退 SAFEOP，报 0x001B。

    在真机上看

    SSC 本身没有统一的日志格式。最实用的做法是在每个 APPL_ 回调入口打一行串口日志，再从主站侧改变状态，对照日志与 AL 寄存器。

    /* 从站固件：在回调里打日志（函数签名以所用 SSC 版本生成的代码为准） */
UINT16 APPL_StartInputHandler(UINT16 *pIntMask)
{
    printf("[ESM] PREOP->SAFEOP\r\n");
    return ALSTATUSCODE_NOERROR;
}
UINT16 APPL_StartOutputHandler(void)
{
    printf("[ESM] SAFEOP->OP\r\n");
    return ALSTATUSCODE_NOERROR;
}
    # 主站侧（不运行应用程序时）
ethercat states -p0 SAFEOP
ethercat reg_read -p0 0x0130 2      # AL Status
ethercat reg_read -p0 0x0134 2      # AL Status Code
# 运行 u6-l1 的程序进 OP 后，Ctrl+C 停掉它，再读：
ethercat reg_read -p0 0x0130 2
ethercat reg_read -p0 0x0134 2
ethercat reg_read -p0 0x0440 2      # SM 看门狗状态（过程数据）
    读数期望值说明
    串口日志[ESM] PREOP->SAFEOPstates SAFEOP 之后出现；没出现说明检查在回调之前就失败了，看 0x0134
    0x01300x0004SAFEOP，无错误位
    0x0130（停主站后）0x0014SAFEOP + bit4 错误指示
    0x0134（停主站后）0x001BSync Manager 看门狗
    0x0440 bit000 = 过程数据看门狗已到期，1 = 正常或未启用

    自测

    误区与关联

    • 误区：ESC 芯片自己会处理 SDO 和状态转换。
      实际上：ESC 只提供 SM 缓冲和 AL 寄存器；读 0x0120、决定能否转换、回 SDO 都是 MCU 固件的工作。固件卡死时，0x0130 会停在旧状态不再变化。
    • 误区：在 PDI 中断或 SYNC0 中断里处理邮箱、打印大量日志。
      实际上：中断里只做有时限的过程数据拷贝和控制计算；邮箱与日志放主循环，否则会挤占控制周期，引起 0x001A 同步错误之类的问题。
    • 误区：看门狗报 0x001B 就是从站固件有问题。
      实际上：最常见的原因是主站停发或周期抖动过大，先查主站程序和 WKC。

    关联：ESM 规范见 u3-l1；邮箱与 SDO 见 u3-l2；同步类型 1C32/1C33 见 u4-l2；从站进 OP 后应用层执行的 CiA402 与电机控制见 u5-l1、u6-l3。

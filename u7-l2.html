故障案例集与诊断决策树

任何症状都先回答三个问题：哪台状态机、哪条通路、哪一层。本课用一棵决策树把 12 个常见故障分到位，并给出先看哪里、怎么推理、怎么修。

定位

本课目标

  1. 用决策树把一个症状分到 ESM 或 CiA402、邮箱或过程数据、以及具体的层。
  2. 对 12 个典型案例说出第一条该敲的命令和该读的寄存器或对象。
  3. 能对一个判不出标准状态的 6041 读数（如 0x0668）给出可执行的结论。

    案例 1从站停在 PREOP，不升 OP
    现象ethercat slaves 显示 PREOP，程序在跑却一直到不了 OP；或短暂到 SAFEOP 又带 E 退回。
    先看哪里ethercat master 的 Phase；ethercat config 是否已挂上从站；dmesg | tail；reg_read -p0 0x0134 2。
    推理IgH 只在应用 activate 且配置挂上从站后才把它往 OP 带。启动时 SDO 或 PDO 配置失败，主站停在 PREOP 并在 dmesg 写出失败对象；从站若拒绝映射，会带 E 并在 0x0134 报 0x001D/0x001E/0x0024/0x0025 等码。
    修复按 dmesg 与 AL 码修正 ecrt_slave_config_sdo*、ecrt_slave_config_pdos 的内容；确认 ecrt_master_activate 已调用、周期任务在收发。身份不符转案例 11。
    关联课u3-l1 · u3-l3 · u6-l1
    案例 2E 标志与 AL 状态码 0x001B
    现象运行中从站变成 SAFEOP 且带 E，0x0134 = 0x001B（同步管理器看门狗）。
    先看哪里reg_read -p0 0x0134 2；reg_read -p0 0x0440 2 看门狗状态；主站周期实测间隔的最大值；看门狗时间 = 0x0400 分频 × 0x0420。
    推理0x001B 表示输出 SM 在看门狗时间内没被写过，从站按规范退到 SAFEOP 并把输出置安全值。原因几乎总在主站侧：周期任务卡住、被抢占、程序退出，或看门狗设得比实际周期间隔还短。ESC 复位默认值约 100 ms，主站或 ESI 常会改写。
    修复保证周期连续（PREEMPT_RT、SCHED_FIFO、mlockall）；看门狗按周期的若干倍设置（IgH：ecrt_slave_config_watchdog）。周期恢复后 IgH 会确认错误并重新请求 OP。
    关联课u2-l2 · u3-l1 · u4-l2
    案例 3域 WKC 比期望少 1
    现象ethercat domains 稳定显示 WorkingCounter 5/6，ecrt_domain_state 报 WC 不完整。
    先看哪里ethercat slaves 各台状态；ethercat domains -v 看每段 FMMU 属于哪台从站；ethercat config。
    推理IgH 的期望 WKC 按每台从站"有输出 +2、有输入 +1"累加；少 1 意味着某一段输入没被计数，少 2 是一段输出，少 3 是一整台读写都没发生。此规则针对同时含输入输出的域（LRW）；纯输出域 IgH 改用 LWR，每台只加 1；纯输入域用 LRD，每台加 1。从站不在 SAFEOP/OP、过程数据 SM 未启用或从站掉线时，ESC 就不会为这段逻辑地址加 WKC。
    修复找到那台从站，按案例 1、2 让它回到 OP；拓扑变化（掉站、多出一台）也会改变实际 WKC，要同步改配置。
    关联课u1-l3 · u2-l3
    案例 46041 = 0x0668，使能不上
    现象总线全 OP、WKC 正常，但写 0x0F 驱动器不进 Operation Enabled；6041 读到 0x0668。
    先看哪里下方逐位表；ethercat upload -p0 --type uint16 0x603F 0 读错误码。
    推理0x0668 & 0x004F = 0x0048，& 0x006F = 0x0068，都不对应 CiA402 状态表里的任何状态。决定性的是 bit3 Fault = 1；标准 Fault 应为掩码 0x004F 取 0x0008（bit6 = 0），这台驱动器同时置了 bit6 Switch On Disabled，属于厂商实现偏差或状态过渡时刻的读数。实用规则：bit3 = 1 就按故障处理。
    修复按 603F 排除原因；6040 先写 0x00 再写 0x80，给 bit7 一个上升沿复位；回到 Switch On Disabled 后按 0x06 → 0x07 → 0x0F 使能，每步等 6041 确认。
    关联课u5-l1 · u5-l3
    案例 5SDO abort 0x08000022
    现象OP 下执行 ethercat download -p0 0x1C12 0 0 之类的写入，返回 abort 0x08000022。
    先看哪里ethercat slaves 当前 ESM 状态；你写的是哪个对象；驱动器手册里该对象的"可写状态"。
    推理0x08000022 的含义是"因当前设备状态，数据不能传送或保存到应用"。典型是在 SAFEOP/OP 下改 PDO 分配或映射（1C12/1C13/1600/1A00），或驱动器在 Operation Enabled 时拒绝改某些参数（因厂商而异）。
    修复PDO 映射交给 ecrt_slave_config_pdos，主站在 PREOP→SAFEOP 之间下发；参数类写入按手册先让驱动器或总线退到允许的状态。
    关联课u3-l2 · u3-l3
    案例 6ethercat upload 超时
    现象ethercat upload 卡几秒后失败，dmesg 有超时记录，或返回 abort 0x05040000（SDO 协议超时）。
    先看哪里ethercat slaves（INIT 下没有邮箱）；ethercat reg_read -p0 0x0800 16 看 SM0/SM1 的地址与长度；sii_read 里的邮箱配置。
    推理邮箱通路要求 SM0/SM1 已配置且固件在处理请求。从站在 INIT、邮箱 SM 的地址或大小与固件期望不一致、或固件主循环被高优先级任务饿死，应答就回不来。
    修复确认从站 ≥ PREOP；按 SII/ESI 核对邮箱配置；从站侧检查主循环是否被中断或长任务阻塞。
    关联课u2-l2 · u3-l2 · u6-l2
    案例 7使能瞬间电机猛冲
    现象CSP 模式下 6040 写 0x0F 的一瞬间，电机猛转一下，甚至报跟随误差。
    先看哪里使能前后几个周期的 607A 与 6064（主站日志或 Wireshark 里的过程数据）；6065 跟随误差窗口。
    推理CSP 下驱动器每周期把 607A 当作位置指令。使能那一刻 607A 若还是 0 或上次的值，而 6064 在别处，位置环会瞬间追一个大误差。
    修复进入 Operation Enabled 之前每个周期令 607A = 6064；使能后从当前实际位置开始插补；把 6065 设为合理值作为最后保护。
    关联课u5-l2 · u6-l1 · u6-l3
    案例 8间歇性 0x001A 同步错误
    现象几小时出现一次 SAFEOP + E，0x0134 = 0x001A，重新请求 OP 又恢复。
    先看哪里主站周期间隔的最大值与分布；cyclictest；驱动器若实现了 0x1C32 的错误计数子索引也可读（因厂商而异）。
    推理DC 同步模式下从站要求过程数据在 SYNC0 之前到达。主站偶发迟到（调度抖动、中断、节能状态切换），从站累计到阈值就报同步错误。
    修复PREEMPT_RT、隔离 CPU、SCHED_FIFO、mlockall；关闭深度节能状态；让发帧时刻相对 SYNC0 留足余量（调整 SYNC0 shift）。
    关联课u4-l2 · u6-l1
    案例 9DC 不同步
    现象多轴在相同指令下动作不齐，或从站报 0x002C、0x0030 等 DC 相关 AL 码。
    先看哪里ethercat slaves -v 的 DC 信息；各从站 reg_read -pN 0x092C 4（系统时间差）是否收敛到很小。
    推理从站间漂移补偿依赖主站每周期把参考时钟的时间分发出去。主站没调用 ecrt_master_sync_slave_clocks、没设 application time，或 SYNC0 激活配置不对，时间差就会发散或 SYNC0 根本不出。
    修复周期里调用 ecrt_master_application_time、ecrt_master_sync_reference_clock、ecrt_master_sync_slave_clocks；ecrt_slave_config_dc 的 assign-activate 值以 ESI 为准（驱动器常见 0x0300）。
    关联课u4-l1 · u6-l1
    案例 10网线插错端口
    现象从站顺序与接线预期不符、某台之后的从站扫不到，或 DC 延时明显不对。
    先看哪里ethercat slaves -v 的端口信息；reg_read -pN 0x0110 2 的 bit4–7（端口 0–3 物理链路）；ethercat graph。
    推理约定端口 0 朝主站（IN）、端口 1 往下游（OUT）。插反后帧的处理顺序与回程路径改变，主站按端口推算的拓扑和传播延时都会错，具体表现因拓扑而异。
    修复按端口 0 进、端口 1 出重新接线，再用 0x0110 确认每台只有期望的端口有链路。
    关联课u1-l1 · u4-l1
    案例 11ESI / 身份不匹配
    现象从站停在 PREOP，ethercat config 显示该配置没有挂上从站，dmesg 报厂商号或产品号不一致（措辞随版本不同）。
    先看哪里ethercat slaves -v 的 Vendor Id / Product code；程序里 ecrt_master_slave_config 的参数；sii_read 的字 0x0008、0x000A。
    推理IgH 只把配置挂到身份一致的从站上。程序或 ESI 按另一个型号或版本写，从站就没有配置可用，主站不会把它往 OP 带。
    修复用 slaves -v 或 cstruct 的实际值更新程序；换过固件的从站 PDO 可能也变了，重新 pdos 核对。
    关联课u2-l4 · u6-l1
    案例 12主站程序退出后从站停在 SAFEOP
    现象Ctrl+C 或程序崩溃后，ethercat slaves 显示 SAFEOP + E，0x0134 = 0x001B。
    先看哪里ethercat master 的 Phase；进程是否真的退出（ps）；0x0134。
    推理周期帧一停，输出 SM 看门狗到期，从站自己退到 SAFEOP 并把输出置安全值，这是设计出来的保护。之后是否回 PREOP 取决于主站：程序已释放主站时 IgH 一般会把从站请求回 PREOP；程序挂住仍占着主站时就停在那里。
    修复写有序退出：先把 6040 降到 0x06 或 0x00 让驱动器停机断使能，再 ecrt_release_master；捕获 SIGINT/SIGTERM 走同一路径。
    关联课u2-l2 · u3-l1 · u6-l1

    案例 4 细看：0x0668 逐位

    6041 判定先用掩码 0x004F，匹配不上再用 0x006F。0x0668 两次都匹配不上，此时不要猜状态，看 bit3。

    状态掩码标准值0x0668 取掩码后匹配？
    Not Ready to Switch On0x004F0x00000x0048否
    Switch On Disabled0x004F0x00400x0048否（多了 bit3）
    Ready to Switch On0x006F0x00210x0068否
    Switched On0x006F0x00230x0068否
    Operation Enabled0x006F0x00270x0068否
    Quick Stop Active0x006F0x00070x0068否
    Fault Reaction Active0x004F0x000F0x0048否
    Fault0x004F0x00080x0048否（多了 bit6）

    其余置位：bit5 Quick Stop = 1（未在快停）、bit9 Remote = 1、bit10 Target Reached = 1；bit4 Voltage Enabled = 0。

    主从对照

    主站侧能看到的证据

    • ethercat master：阶段、丢帧计数。
    • ethercat domains / ecrt_domain_state：WKC 当前与期望。
    • ethercat config：配置是否挂上、请求的状态。
    • dmesg：SDO/PDO 配置失败、身份不符、状态切换被拒的原文。
    • 应用自己记录的周期间隔、607A 与 6064 轨迹。

    从站侧留下的证据

    • 0x0130/0x0134：ESM 状态、错误位、AL 状态码。
    • 0x0110、0x0300 起：端口链路与错误计数。
    • 0x0440：SM 看门狗；0x092C：DC 时间差。
    • 6041、603F：驱动器状态与错误码。
    • SDO abort code：邮箱请求为什么被拒。

    自测

    误区与关联

    • 误区：电机不动就先查驱动器参数。
      实际上：先确认总线在 OP、WKC 完整；ESM 或通路有问题时，驱动器读到的是过期或安全值，查参数只会浪费时间。
    • 误区：6041 一定能对上状态表中的某一行。
      实际上：厂商实现和过渡时刻都会出现"判不出"的值；按掩码逐个比对，匹配不上时以 bit3 Fault 为准，并读 603F。
    • 误区：从站掉到 SAFEOP 就是故障。
      实际上：看门狗触发的 SAFEOP 是从站在执行保护；真正要修的是让它失去周期数据的主站侧原因。

    关联：命令用法回看 u7-l1；AL 状态码 u3-l1；abort code u3-l2；6041 解码 u5-l1。这是最后一课，建议从系统总图再走一遍全链路。

EEPROM/SII 与 ESI：从站的身份证

主站扫描到一台从站时，只知道"位置 0 有一台"。它是谁、邮箱在哪、有哪些 SM，全靠读从站 EEPROM 里的 SII；配置工具再拿 SII 里的身份去和 ESI XML 文件对照。

定位

本课目标

  1. 说出 SII 头区（字 0x0000–0x003F）里有什么，以及从字 0x0040 开始的类别区有哪些类别。
  2. 解释主站怎样经 0x0500 EEPROM 接口读 SII，靠哪几个字识别从站。
  3. 解释 ESI XML 与 SII 的关系：谁从谁生成，谁在什么时候被用到。

    机制拆解

    SII 头区：字 0x0000–0x003F

    SII 以 16 位字编址，字地址 × 2 才是字节偏移，hexdump 看到的是字节偏移。前 8 个字由 ESC 上电自动装载进寄存器，其余由主站读取使用。

    字地址字节偏移内容备注
    0x0000–0x00030x00PDI 控制、PDI 配置、SYNC 脉宽、扩展 PDI 配置上电装载进 0x0140、0x0150 等寄存器
    0x00040x08站别名装载进 0x0012
    0x00070x0E字 0–6 的校验和错了 ESC 不装载配置
    0x00080x10Vendor ID（2 字）ETG 分配的厂商号
    0x000A0x14Product Code（2 字）厂商自定
    0x000C0x18Revision Number（2 字）厂商自定的版本号
    0x000E0x1CSerial Number（2 字）很多厂商填 0
    0x0014–0x00170x28Bootstrap 收/发邮箱偏移与大小BOOT 状态（FoE 升级）用
    0x0018–0x001B0x30标准收邮箱偏移、大小，发邮箱偏移、大小"收"是从站视角，即 SM0
    0x001C0x38支持的邮箱协议bit0 AoE、bit1 EoE、bit2 CoE、bit3 FoE、bit4 SoE、bit5 VoE
    0x003E–0x003F0x7CEEPROM 容量、SII 版本编码见 ETG.2010

    类别区：从字 0x0040 开始的链表

    每个类别以两个字开头：类别类型、数据长度（单位：字），数据紧随其后，下一个类别接在后面，类型 0xFFFF 表示结束。主站顺着链表走一遍，就拿到名称字符串、默认 SM、PDO 描述等。

    类型号名称内容
    10Strings字符串表，其他类别用序号引用（设备名、组名等）
    30General名称序号、CoE/FoE/EoE 细节、端口物理类型、EBus 电流等
    40FMMU每字节一个 FMMU 的用途（输出、输入、SM 状态）
    41SyncM每 SM 8 字节：物理起始 2、长度 2、控制字节 1、状态 1、使能 1、SM 类型 1
    50 / 51TXPDO / RXPDO默认 PDO 及其条目（索引、子索引、位长）
    60DC分布式时钟的同步模式参数

    经 0x0500 接口读一个字

    EEPROM 挂在 ESC 的 I²C 上，主站不能直接访问，只能借 ESC 的 EEPROM 接口寄存器"代读"。每次读回 4 或 8 字节，主站循环推进字地址把整个 SII 读完。

    步骤寄存器动作
    10x0500/0x0501确认 EEPROM 由 EtherCAT 侧掌控（不在 PDI 手里）
    20x0504写入要读的字地址，如 0x0008
    30x0502写读命令（命令位 bit8–10 = 001）
    40x0502轮询 bit15 忙位直到清零；bit11–14 是错误位，含义见芯片手册
    50x0508读数据：4 或 8 字节，由 0x0502 bit6 指示

    ESI 与 SII 的关系

    ESI 是厂商随产品提供的完整 XML 描述，SII 是烧在从站 EEPROM 里的紧凑子集，通常由工具从 ESI 生成。两者应该一致，但改了固件忘了更新其一的情况很常见。

    ESI（EtherCAT Slave Information）SII（Slave Information Interface）
    在哪主站侧文件，XML从站 EEPROM，二进制
    内容身份、SM、所有可选 PDO、对象字典描述、DC 模式、初始化命令等身份、邮箱、默认 SM/FMMU/PDO、字符串、DC
    谁用配置工具（如 TwinCAT）离线组网、对照设备任何主站在线扫描；IgH 只用它
    规范ETG.2000ETG.2010

    主从对照

    主站做什么

    • 扫描后逐台经 0x0500–0x050F 读 SII，缓存下来。
    • 用字 0x0008–0x000D 的厂商号、产品号、版本号判断"这是谁"。
    • 用字 0x0018–0x001C 和 SyncM 类别配置 SM0/SM1，进 PREOP。
    • IgH：把 SII 身份和程序里 ecrt_master_slave_config() 给的厂商号、产品号比较，不匹配就不挂这份配置。
    • TwinCAT 类工具：再拿身份去 ESI 库里找设备描述。

    从站做什么

    • 上电时 ESC 自动读字 0x0000–0x0007，配置 PDI 和站别名；校验和错则不装载。
    • 之后 ESC 按主站写的命令代为读写 EEPROM，固件一般不参与。
    • 固件需要时可经 PDI 接管 EEPROM（0x0500/0x0501 决定归属），用完要交还。
    • 固件升级后若 PDO 或邮箱变了，厂商应同步更新 SII，否则主站按旧值配置。

    在真机上看

    ethercat sii_read -p0 | hexdump -C | head -8   # 原始 SII，字节偏移
ethercat sii_read -p0 -v                       # 按类别解析后的文本
ethercat slaves -p0 -v                         # 身份与邮箱配置
ethercat xml -p0 > slave0.xml                  # 主站据 SII 生成的描述
    读数期望值说明
    hexdump 0x10–0x13Vendor ID，小端字 0x0008；如 34 12 00 00 即 0x00001234
    hexdump 0x14–0x1BProduct Code、Revision字 0x000A、0x000C，小端
    hexdump 0x30–0x37收邮箱偏移/大小、发邮箱偏移/大小字 0x0018–0x001B，与 slaves -v 的邮箱行一致
    hexdump 0x38如 0c 00字 0x001C：CoE + FoE
    hexdump 0x80第一个类别类型字 0x0040，常见为 0a 00（Strings）
    slaves -v 身份段Vendor Id / Product code / Revision number与上面 hexdump 读数一致
    xml 输出含 Vendor、ProductCode、Sm、RxPdo/TxPdo由 SII 生成，不等于厂商 ESI 原文，缺对象字典描述

    自测

    误区与关联

    • 误区：SII 就是 ESI 的二进制拷贝。
      实际上：SII 只是 ESI 的一个紧凑子集，没有对象字典描述，只有默认 PDO；两者由不同的人在不同时间维护，可能不同步，出问题时以从站实际 SII 为准。
    • 误区：改了主站上的 ESI 文件，从站的行为就变了。
      实际上：从站只认自己 EEPROM 里的 SII。真要改需要 ethercat sii_write 写回，写坏了 ESC 可能装载错误的 PDI 配置，必须先备份。
    • 误区：文档里写的 SII 地址 0x0008 就是 hexdump 里的 0x0008。
      实际上：SII 用字地址，hexdump 用字节偏移，要乘 2。

    关联：读到身份和邮箱配置后，主站就能把从站从 INIT 带到 PREOP，见下一单元 u3-l1；SII 里的默认 PDO 在 u3-l3 会被 CoE 对象 1C12/1C13 覆盖。

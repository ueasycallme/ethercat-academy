寻址与命令：飞行读写与 WKC

数据报头里的命令码决定"怎么找从站、读还是写"；每台从站在帧流过时就地读写，并把 WKC 按规则加上去，主站靠 WKC 判断有多少次读写真正发生了。

定位

本课目标

  1. 区分自增（位置）寻址、站地址寻址、广播、逻辑寻址，各用在什么阶段。
  2. 说出每类命令的 WKC 增量：只读 +1、只写 +1、读写命令读 +1 / 写 +2 / 都成功 +3。
  3. 解释"飞行读写"：从站在帧流过时读写，帧不停留。

    SAFEOP / OP
    SAFEOP 输入有效、输出保持安全态；到 OP 输出才生效。u3-l1

    四种寻址方式

    命令码本身就带着寻址方式：AP 开头按位置，FP 开头按站地址，B 开头广播，L 开头按逻辑地址。位置寻址时 32 位地址拆成 ADP（2 B，找谁）和 ADO（2 B，从站内的寄存器偏移）。

    方式命令地址字段哪台处理典型用途
    自增（位置）APRD APWR APRW ARMWADP = −位置号；ADO = 寄存器每台把 ADP 加 1 后转发；收到 ADP = 0 的那台处理启动扫描，分配站地址之前
    站地址FPRD FPWR FPRW FRMWADP = 站地址；ADO = 寄存器ADP 等于本站 0x0010（或已启用的别名 0x0012）的那台配置、邮箱、诊断
    广播BRD BWR BRWADO = 寄存器；ADP 不用于寻址所有从站数从站、读全体状态、同时写全体
    逻辑LRD LWR LRW32 位逻辑地址FMMU 映射覆盖了该地址段的从站周期过程数据

    BRD 时每台从站把自己寄存器的值与帧里的数据按位或，所以读回的是全体的"或"。

    WKC 增量规则

    每台从站只在读写真正成功时才加 WKC：没命中、没映射、或该区域当前不可访问都不加。读写命令把"读"和"写"分别计 1 和 2，主站从总数就能分辨是哪一半没成功。

    命令类每台从站成功时例
    只读：APRD FPRD BRD LRD读成功 +1BRD 3 台在线 → WKC = 3
    只写：APWR FPWR BWR LWR写成功 +1FPWR 命中 → WKC = 1
    读写：APRW FPRW BRW LRW读成功 +1，写成功 +2，都成功 +3LRW 一台既有输出又有输入 → +3
    读多写：ARMW FRMW被寻址那台读成功 +1；其余每台写成功 +1用于分发参考时钟（u4-l1）

    期望 WKC 怎么算

    周期 LRW 的期望值按每台从站在这个数据报里的映射逐台加：有输出（被写）加 2，有输入（被读）加 1。IgH 自动为每个域算好这个数，并在每周期比较。此规则针对同时含输入输出的域（LRW）；纯输出域 IgH 改用 LWR，每台只加 1；纯输入域用 LRD，每台加 1。

    从站映射贡献
    从站 1（伺服驱动器）RxPDO 输出 + TxPDO 输入2 + 1 = 3
    从站 2（数字输入模块）只有输入1
    从站 3（数字输出模块）只有输出2
    期望 WKC6

    主从对照

    主站做什么

    • 按阶段选寻址方式：先广播数从站，再按位置给每台写站地址（0x0010），之后配置和诊断都用站地址，周期过程数据用 LRW。
    • IgH 空闲时周期性发 BRD 读 0x0130：WKC 就是在线从站数，数据是全体 AL 状态的按位或。
    • 为每个数据报算好期望 WKC；周期里比较实际值，IgH 在 ecrt_domain_state() 的 wc_state 里给出 ZERO / INCOMPLETE / COMPLETE。

    从站做什么

    • ESC 读到数据报头就判断是否命中：位置寻址先把 ADP 加 1 再转发；站地址寻址比 0x0010；逻辑寻址查自己的 FMMU。
    • 命中就在数据流过时读或写，并按规则累加 WKC；整个过程由 ESC 硬件完成，从站 CPU 不参与。
    • 从站从不单独应答：所有结果都写回同一帧里，随帧回到主站。

    在真机上看

    ethercat reg_read -p1 --type uint16 0x0010 2   # 位置 1 那台的站地址（扫描时由主站写入）
ethercat reg_read -p1 --type uint16 0x0130 2   # 它的 AL 状态；IgH 用站地址寻址去读
ethercat domains                               # 每个域的 WorkingCounter 实际/期望
dmesg | grep -i "working counter"              # WKC 变化时 IgH 会打日志
    读数期望值说明
    0x0010非 0，各台互不相同站地址由主站分配：IgH 扫描时设为位置号 + 1，即 1、2、3…；其他主站可能不同
    WorkingCounter6/6（按你的映射）斜杠左边是最近一次实际值，右边是期望值
    期望值Σ（有输出 2 + 有输入 1）按上面的表逐台加，核对 IgH 算的数
    实际 < 期望例如 4/6有从站没参与交换：掉线、没到 SAFEOP/OP、或映射不对；先看 ethercat slaves
    实际 = 00/6这帧没有一台处理成功，常见于帧没回来或全体不在可交换状态

    自测

    误区与关联

    • 误区：WKC 就是"应答的从站数"。
      实际上：只读、只写命令每台 +1，但读写命令按读 1、写 2 加权；LRW 的期望值要按每台的输出/输入映射逐台算。
    • 误区：WKC 对上了，数据就一定对。
      实际上：WKC 只说明读写发生了几次，不校验数据内容，也不说明驱动器已进入 Operation Enabled。
    • 误区：位置寻址一直用下去就行。
      实际上：位置号随接线变，前面插拔一台后面全变；分配站地址后应改用站地址或逻辑寻址。

    关联：LRW 里"哪段逻辑地址对应哪台从站的哪块内存"由 FMMU 决定，见 u2-l3；ARMW/FRMW 分发参考时钟见 u4-l1；WKC 不完整的排查见 u7-l2。

邮箱协议族与 CoE SDO

SDO 是"一问一答"的配置通路：主站把请求写进 SM0，从站把应答放进 SM1。同一个邮箱里跑着 AoE/EoE/CoE/FoE/SoE/VoE 一族协议；本课先认清这一族，再逐字节拆开一次 CoE SDO 下载，讲清快速、普通、分段传输、abort code 和驱动器主动上报的 Emergency。

定位

本课目标

  1. 逐字节读懂一帧 SDO 请求：邮箱头 6 字节、CoE 头 2 字节、SDO 8 字节。
  2. 区分快速传输、普通传输和分段传输，会从命令字节判断是哪一种。
  3. 看到 abort code 或 Emergency 报文，能说出原因和下一步该查什么。

    机制拆解

    邮箱协议族：一个邮箱，多种协议

    SM0/SM1 邮箱只是搬运通道，里面装什么协议由邮箱头 Type 字段决定。关节驱动器最常用 CoE（参数与 SDO）和 FoE（固件升级，BOOT 状态下用）。从站支持哪些协议，看 SII 字地址 0x001C 的邮箱协议字和 ESI 里的 Mailbox 元素。

    Type协议全称典型用途SII 0x001C 位
    0ERR邮箱错误应答从站回报邮箱层错误（如不支持的 Type）—
    1AoEADS over EtherCATBeckhoff ADS 访问bit0
    2EoEEthernet over EtherCAT在邮箱里隧道传标准以太网帧（如从站 Web 页面）bit1
    3CoECANopen over EtherCAT对象字典、SDO、Emergency；CiA402 驱动器的主力bit2
    4FoEFile access over EtherCAT下载固件、读写文件，常在 BOOT 状态bit3
    5SoEServo drive profile over EtherCATSERCOS 驱动器行规（IDN 参数）bit4
    15VoEVendor specific over EtherCAT厂商自定义bit5

    一帧 SDO 的三层头

    邮箱头告诉 ESC 后面有多少字节、是什么协议；CoE 头说明是 SDO 请求还是应答；SDO 部分才是命令、对象号和数据。所有多字节字段都是小端。

    字节偏移字段位宽本例值说明
    0–1Length160x000A邮箱头之后的字节数（CoE 头 2 + SDO 8）
    2–3Address160x0000站地址字段，主站填法因实现而异，按 ETG.1000.6
    4Channel / Priority6 + 20x00通道 bit0–5，优先级 bit6–7，一般为 0
    5Type / Cnt4 + 3 + 10x13Type bit0–3：3 = CoE（其他取值见上表）；Cnt bit4–6：1–7 循环，用来识别重发；bit7 保留
    6–7CoE 头9 + 3 + 40x2000Number bit0–8（SDO 时为 0）；保留 3 位；Service bit12–15：2 = SDO 请求，3 = SDO 应答，1 = 紧急报文
    8SDO 命令80x2F见下表
    9–10Index160x6060对象索引，线上为 60 60
    11Subindex80x00子索引
    12–15Data3208 00 00 00快速传输的数据；普通传输时是总长度

    CoE 头：服务类型

    CoE 头的高 4 位 Service 说明这一帧 CoE 是什么：SDO 只是其中两种，从站主动上报的 Emergency 也走同一个邮箱。邮箱里的 PDO 服务（4–7）极少用，关节控制的 PDO 都走 SM2/SM3 过程数据。

    Service名称方向说明
    1Emergency从→主从站出错时主动放进 SM1，见本课最后一节
    2SDO 请求主→从本课主动画的请求（CoE 头小端 00 20）
    3SDO 应答从→主含 abort（CoE 头小端 00 30）
    4TxPDO从→主经邮箱传 PDO
    5RxPDO主→从经邮箱传 PDO
    6TxPDO 远程请求主→从请求从站经邮箱发 TxPDO
    7RxPDO 远程请求从→主请求主站经邮箱发 RxPDO
    8SDO Information双向读对象字典目录与描述，ethercat sdos 靠它

    SDO 命令字节怎么读

    高 3 位是命令码（主站发叫 ccs，从站回叫 scs）；初始化类命令里 e = 1 表示快速传输，s = 1 表示给出了长度，n 是 4 字节数据里"没用上"的字节数。bit4 在 CoE 里是 Complete Access 标志，普通访问为 0。

    bit7–5bit4bit3–2bit1bit0
    ccs / scsCAnes
    命令字节方向含义
    0x2F / 0x2B / 0x27 / 0x23主→从快速下载 1 / 2 / 3 / 4 字节（ccs = 1，e = 1，s = 1，n = 3/2/1/0）
    0x21主→从普通下载：Data 放 4 字节总长度，数据跟在后面
    0x60从→主下载应答成功（scs = 3）
    0x40主→从上传请求（ccs = 2），Data 为 0
    0x4F / 0x4B / 0x47 / 0x43从→主快速上传应答 1 / 2 / 3 / 4 字节
    0x41从→主普通上传应答：Data 为总长度，数据跟在后面
    0x80双向Abort：Data 为 4 字节 abort code

    快速、普通与分段

    不超过 4 字节的对象（6040、6060、607A 等）用快速传输，一问一答就完。更长的对象用普通传输，数据紧跟在长度后面；只有当数据超过邮箱容量时，才继续用分段请求逐段搬运，toggle 位 t 在 0/1 间交替防止丢段。

    abort code：出错时从站回什么

    从站不能完成请求时，回一帧命令字节 0x80 的 SDO，索引和子索引照抄请求，4 字节数据就是 abort code。码的高位字节大致分类：0x05 协议层、0x06 访问与对象、0x08 应用与状态。

    abort code含义下一步查什么
    0x05040000SDO 协议超时从站固件忙或分段中断；查邮箱周期、从站负载
    0x06010000不支持该访问对只读对象做了下载，或反之；查 ESI 的访问属性
    0x06020000对象不存在索引写错，或这台驱动器没有该对象
    0x06070010数据类型不匹配，服务参数长度不符长度写错，如对 16 位对象写了 4 字节；核对 --type
    0x06090011子索引不存在子索引写错；VAR 类对象只有子索引 0
    0x08000022当前设备状态下不能传输或存储在错误的 ESM 状态改 PDO 映射（例如在 SAFEOP/OP 写 1C12），或驱动器状态不允许

    Emergency 报文：驱动器主动报错

    驱动器发生故障时，不等主站来问，主动把一帧 CoE Service = 1 的 Emergency 放进 SM1，主站下次轮询邮箱时读到。数据固定 8 字节：错误码与 603F 同一编码，错误寄存器与 0x1001 相同，后 5 字节由厂商定义。历史故障可回读 0x1003 预定义错误域（子索引 0 为条数，子索引 1 为最近一条）。

    字节字段示例说明
    0–1错误码（小端）10 43 = 0x4310与 603F 同一编码；0x4310 在 CiA 402 中为驱动器过温
    2错误寄存器0x09与 0x1001 相同：bit0 通用错误，bit3 温度
    3–7厂商数据xx xx xx xx xx含义看驱动器手册，因厂商而异

    IgH 收到后打印到内核日志，可用 dmesg | grep -i emerg 查看，打印格式因 IgH 版本而异；应用侧也可从主站取出 Emergency 报文，接口以所用 IgH 版本手册为准。

    主从对照

    主站做什么

    • 确认从站至少在 PREOP，且 SM1 里没有未读的旧应答。
    • 组装邮箱头 + CoE 头 + SDO，用 FPWR 写满 SM0 整个缓冲区（写到最后一个字节 SM 才变"满"）。
    • 周期性 FPRD 读 SM1 状态（0x080D bit3 = 邮箱满），满了再 FPRD 读出整个 SM1。
    • 一次 SDO 往返至少跨两个周期（请求在第 1 帧写进 SM0，应答最早在第 2 帧从 SM1 读回），逐步动画见 u2-l2。
    • 核对应答的索引、子索引；命令字节 0x80 时解出 abort code，上报给应用。超时由主站自己计时。

    从站做什么

    • ESC 在 SM0 写满时触发 PDI 中断或置事件位；固件读出 SM0，SM0 回到"空"，主站可发下一帧。
    • 协议栈按 Type = 3 交给 CoE，按 Service = 2 交给 SDO 服务，查对象字典的存在性、访问权限、长度和当前状态。
    • 成功就读写对象，失败就准备 abort code。
    • 把应答写进 SM1；主站读完后 SM1 变"空"，才能放下一条应答。

    在真机上看

    从站需在 PREOP 或更高。IgH 的 upload/download 参数是"索引 子索引 [值]"；从站不支持 SDO Information 时必须用 --type 指定类型。

    # 读状态字（快速上传，2 字节）
ethercat upload -p0 0x6041 0 --type uint16
# 写运行模式为 CSP（快速下载，1 字节，命令字节 0x2F）
ethercat download -p0 0x6060 0 8 --type int8
ethercat upload -p0 0x6061 0 --type int8
# 读厂商号，对照 ethercat slaves -v
ethercat upload -p0 0x1018 1 --type uint32
# 故意读一个不存在的子索引，看 abort code
ethercat upload -p0 0x6041 5 --type uint16
# 列出对象字典（需从站支持 SDO Information）
ethercat sdos -p0
# 驱动器报过故障后：看 Emergency 日志与历史错误
dmesg | grep -i emerg
ethercat upload -p0 0x1003 0 --type uint8
ethercat upload -p0 0x1003 1 --type uint32
    命令期望说明
    upload 0x6041 0如 0x0250十六进制 + 十进制两列；具体值按 u5-l1 的掩码判读
    download 0x6060 0 8无输出成功时静默；失败打印 abort code
    upload 0x6061 00x08 8驱动器接受了 CSP；有的驱动器要在 CiA402 某些状态下才更新
    upload 0x1018 1厂商号与 ethercat slaves -v 的 Vendor Id 一致
    upload 0x1003 00 或故障条数无故障历史时为 0；支持 1003 与否因厂商而异（不支持回 0x06020000）
    upload 0x6041 5abort 0x06090011多数驱动器如此；少数回 0x06020000 等，因厂商而异

    自测

    误区与关联

    • 误区：SDO 和 PDO 都是"读写对象"，所以可以在周期任务里用 SDO 发目标位置。
      实际上：SDO 走邮箱，一次往返要若干个总线周期且时长不确定；周期数据必须走 PDO。
    • 误区：大于 4 字节一定要分段。
      实际上：CoE 普通传输可以把数据直接跟在长度后面放进同一帧邮箱；只有超过邮箱容量才需要分段。
    • 误区：upload 超时就说明对象不存在。
      实际上：对象不存在从站会明确回 0x06020000；超时多半是从站不在 PREOP 以上、邮箱配置错或固件卡住，先查 ESM 状态。

    关联：对象字典的结构与索引分区见 u3-l0；SM 邮箱满/空握手见 u2-l2；ESM 什么时候打开邮箱见 u3-l1；用 SDO 写 PDO 映射见下一课 u3-l3；6041/6060 的含义见 u5-l1、u5-l2；603F 与故障处理见 u5-l3。

PDO 映射与过程映像

周期帧里每个字节是谁、在哪个偏移，全由三层对象决定：映射对象（1600/1A00）选内容，分配对象（1C12/1C13）挂到 SM，主站再用 FMMU 把 SM 排进域。本课把这条链从头算到 C 代码里的偏移。

定位

本课目标

  1. 读懂映射项的 32 位编码：索引 16 位、子索引 8 位、位长 8 位。
  2. 解释 1C12/1C13 怎样把 PDO 挂到 SM2/SM3，并算出 SM 长度。
  3. 从映射一路算出域里每个变量的字节偏移，读懂 ethercat cstruct 的输出。

    机制拆解

    映射项的 32 位编码

    映射对象的每个子索引是一个 UINT32：高 16 位索引、中 8 位子索引、低 8 位位长（单位 bit）。子索引 0 是条目个数。索引为 0 的条目是填充位，用来对齐。

    映射项索引子索引位长对象
    0x604000100x60400x000x10 = 16控制字
    0x607A00200x607A0x000x20 = 32目标位置
    0x604100100x60410x000x10 = 16状态字
    0x606400200x60640x000x20 = 32实际位置
    0x000000080x00000x0088 位填充

    分配：从 PDO 到 SM 长度

    1C12 列出挂在 SM2（输出）上的 RxPDO，1C13 列出挂在 SM3（输入）上的 TxPDO。SM 长度等于所分配 PDO 的位长之和换成字节，主站据此写 SM 长度寄存器；与从站预期不一致时，从站在 PREOP→SAFEOP 拒绝并报 0x001D / 0x001E。

    动态映射：在 PREOP 里按顺序写

    映射可改的从站（ESI 里标明）只允许在 PREOP 改，在 SAFEOP/OP 改通常回 abort 0x08000022。关键是"先清零子索引 0，写完条目，再写回个数"，从站在写子索引 0 时才校验整张表。IgH 在 ecrt_slave_config_pdos() 配置后会自动按这个顺序写。

    #SDO 下载作用
    11C12:00 = 0先解除 SM2 的分配
    21600:00 = 0清空映射，允许改条目
    31600:01 = 0x60400010第 1 个条目
    41600:02 = 0x607A0020第 2 个条目
    51600:00 = 2写回个数，从站校验映射
    61C12:01 = 0x1600把 1600 挂到 SM2
    71C12:00 = 1写回个数，分配生效

    1A00 / 1C13 同理。固定映射的从站只能在 1C12/1C13 里选预定义的 PDO，甚至连分配也不能改，写入会被 abort，具体以 ESI 为准。

    从映射到域偏移与 C 代码

    应用按顺序注册 PDO 条目时，IgH 为每个用到的 SM 在域里分配一段连续空间并配 FMMU。本例先注册输出，于是 SM2 的 6 字节在前、SM3 的 6 字节在后，域共 12 字节，一帧 LRW 读写全部。

    对象所在 SM域偏移长度读写宏
    6040 控制字SM202EC_WRITE_U16(pd + off_cw, v)
    607A 目标位置SM224EC_WRITE_S32(pd + off_tp, v)
    6041 状态字SM362EC_READ_U16(pd + off_sw)
    6064 实际位置SM384EC_READ_S32(pd + off_ap)
    static unsigned int off_cw, off_tp, off_sw, off_ap;
const ec_pdo_entry_reg_t regs[] = {
    {0, 0, VID, PID, 0x6040, 0, &off_cw},   /* → 0 */
    {0, 0, VID, PID, 0x607A, 0, &off_tp},   /* → 2 */
    {0, 0, VID, PID, 0x6041, 0, &off_sw},   /* → 6 */
    {0, 0, VID, PID, 0x6064, 0, &off_ap},   /* → 8 */
    {}
};
ecrt_domain_reg_pdo_entry_list(domain, regs);

    主从对照

    主站做什么

    • 应用用 ec_sync_info_t 数组描述想要的分配和映射，调用 ecrt_slave_config_pdos()。
    • PREOP 里按"清零、写条目、写个数"的顺序 SDO 下载 1600/1A00、1C12/1C13。
    • 按映射算 SM2/SM3 长度写入 SM 寄存器，为每段配 FMMU，把逻辑地址排进域。
    • 把每个注册条目的域偏移回填给应用，周期里按偏移读写域内存。

    从站做什么

    • 写子索引 0 时校验映射：对象存在、可映射、方向对、总长不超限；不合法回 abort。
    • P→S 时核对 SM2/SM3 长度与自己算的映射总长，不符报 0x001D/0x001E，映射非法报 0x0024/0x0025。
    • 运行时固件按映射表把 SM2 的字节拆给 6040、607A，再把 6041、6064 拼进 SM3。
    • ESC 本身不懂映射，只按 SM 和 FMMU 搬字节。

    自测

    误区与关联

    • 误区：把域指针强转成一个普通 C 结构体来读写。
      实际上：偏移 2 的 32 位目标位置不按 4 字节对齐，普通结构体会被编译器补齐成 0、4、8、12；要么结构体加 packed，要么用 EC_READ_*/EC_WRITE_* 宏，它们还处理了小端。
    • 误区：改了 ESI 或主站里的映射，驱动器就一定按新映射发数据。
      实际上：映射是写进驱动器对象字典的，要在 PREOP 真的下载成功；固定映射的驱动器会拒绝，用 ethercat pdos 核对实际值。
    • 误区：1C12 里填映射项、1600 里填 PDO 号。
      实际上：层次反过来：1C12/1C13 的条目是 PDO 号（0x1600、0x1A00），1600/1A00 的条目才是"索引|子索引|位长"。

    关联：FMMU 与逻辑地址见 u2-l3；映射用 SDO 写入见 u3-l2；控制字、状态字各位的含义见下一课 u5-l1；周期里怎么读写域见 u6-l1。

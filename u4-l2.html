同步模式与主站周期

有了 DC 时钟，驱动器还要决定"应用周期由谁触发"：自己的定时器、帧的到达，还是 SYNC0。选了 DC 同步后，主站的发帧时刻就必须对准 SYNC0 并留出余量，否则从站报同步错误。

定位

本课目标

  1. 区分 Free Run、SM 同步、DC 同步三种模式：各由什么事件触发应用周期。
  2. 解释主站周期如何与 DC 系统时间锁相，以及 IgH 里对应的几个调用。
  3. 说出抖动来源，以及抖动吃掉安全余量后从站会报什么。

    三种同步模式

    同步模式说的是"从站应用（控制周期、采样、输出生效）由什么事件触发"。驱动器通过对象 0x1C32（输出侧）与 0x1C33（输入侧）的子索引 1 声明当前模式，主站在 PREOP 可写入。

    1C32:01模式触发事件应用周期的抖动来自适合
    0Free Run从站本地定时器与主站无关，但相位也不对齐慢速 IO、不关心同步
    1SM 同步输出 SM（通常 SM2）写入事件，即帧到达主站发帧抖动 + 网络单轴、周期要求不高
    2DC 同步 SYNC0ESC 的 SYNC0 脉冲几乎只剩 DC 本身的误差多轴插补、CSP/CSV/CST
    3DC 同步 SYNC1ESC 的 SYNC1 脉冲同上需要第二个时刻的设备

    驱动器支持哪些模式看子索引 4（支持的同步类型位图）与 ESI；其余取值和细节以 ETG.1020 为准。

    0x1C32 / 0x1C33 关键子索引

    子索引名称用途
    01Synchronization Type上表的模式
    02Cycle Time应用周期，ns；DC 模式下应与 SYNC0 周期一致
    03Shift Time相关事件到动作（如输出生效）的时间，ns；具体语义以 ETG.1020 为准
    04Synchronization Types Supported支持的模式位图
    0B / 0CSM-Event Missed / Cycle Time Too Small错误计数，驱动器不一定实现
    20Sync Error同步错误标志，驱动器不一定实现

    注意：IgH ecrt_slave_config_dc 里的 sync0_shift 是主站配置 SYNC0 相位用的，和 1C32:03 不是同一个量。

    主站周期怎么对准 SYNC0

    DC 模式下，SYNC0 的起始时间由主站根据自己的"应用时间"算出并写进 0x0990，所以 SYNC0 天然落在主站周期网格上再加 sync0_shift。之后只要主站周期与参考时钟不相对漂移，帧就总在 SYNC0 前到达；IgH 有两种做法：让参考时钟跟主站（ecrt_master_sync_reference_clock 把应用时间写给参考时钟），或让主站跟参考时钟（读 ecrt_master_reference_clock_time 调整自己的唤醒时刻）。

    /* 配置阶段（activate 之前） */
ecrt_slave_config_dc(sc, 0x0300,      /* assign_activate：常见值，以 ESI 为准 */
                     1000000, 400000, /* sync0_cycle 1 ms, sync0_shift（示例） */
                     0, 0);           /* 不用 SYNC1 */

/* 周期里 */
clock_gettime(CLOCK_MONOTONIC, &now);
ecrt_master_application_time(master, TIMESPEC2NS(now));
ecrt_master_sync_reference_clock(master);
ecrt_master_sync_slave_clocks(master);
ecrt_domain_queue(domain);
ecrt_master_send(master);

    assign_activate 写进 0x0980：0x0300 即 0x0981 = 0x03（周期运行 + SYNC0），是很多驱动器的值，但因厂商而异，按 ESI 里 AssignActivate 取。

    抖动从哪来

    来源在哪一层怎么压
    周期线程唤醒延迟实时周期循环 / OSPREEMPT_RT、SCHED_FIFO、mlockall、CPU 隔离
    周期内计算时间波动规划器、实时循环把重计算移出周期线程
    网卡驱动与中断网卡驱动IgH 原生驱动（如 igb、e1000e）替代 generic
    线上传输网线与 ESC从站多时帧往返更长，余量按最远一台算

    主从对照

    主站做什么

    • PREOP 时用 SDO 写 1C32/1C33（或交给驱动器按 ESI 默认），并用 ecrt_slave_config_dc 配 SYNC0 周期与相位。
    • 每周期调用 ecrt_master_application_time、同步时钟、再发帧，保持周期与参考时钟锁相。
    • 保证最坏情况下帧也在 SYNC0 之前到达最远的从站。

    从站做什么

    • 按 1C32:01 选择触发源：本地定时器、SM2 事件或 SYNC0 中断。
    • DC 模式下在 SYNC0 中断里取用最新的输出、采样输入。
    • 发现 SYNC0 到来时新数据没到（或 SM 事件丢失）达到阈值，退回 SAFEOP 并报 AL 码；阈值因厂商而异。

    在真机上看

    先量主站周期线程的唤醒延迟（与主站程序同优先级、同周期）：

    sudo cyclictest -m -S -p 90 -i 1000 -l 100000 -q

    再看驱动器选的同步模式和从站状态：

    ethercat upload -p0 --type uint16 0x1C32 1
ethercat upload -p0 --type uint32 0x1C32 2
ethercat slaves
ethercat reg_read -p0 0x0134 2
    读数期望值说明
    cyclictest Max明显小于安全余量PREEMPT_RT 上常见几十 µs 量级，因硬件与负载而异
    1C32:010x0002DC SYNC0 模式；0x0001 为 SM 同步
    1C32:021000000与 SYNC0 周期（0x09A0）一致，单位 ns
    域 WKC每周期恒等于期望值应用里打印 ecrt_domain_state 的 working_counter，偶发变小说明丢帧或晚到
    slaves 状态列OP，标志 +SAFEOP 且标志 E 时读 0x0134
    0x01340x00000x001A 同步错误；0x002C 致命同步错误；0x0030 DC 同步配置无效

    自测

    误区与关联

    • 误区：ESC 支持 DC，驱动器就一定工作在 DC 同步模式。
      实际上：模式由 1C32:01 决定，还要主站配置并激活 SYNC0；没激活时很多驱动器会拒绝进 SAFEOP/OP。
    • 误区：sync0_shift 设成 0 最好，延迟最小。
      实际上：shift 太小时帧可能晚于 SYNC0，偶发同步错误；shift 要大于最坏抖动加处理与传输时间。
    • 误区：0x0300 是所有驱动器通用的 assign_activate。
      实际上：它只是常见值，要用 SYNC1 或厂商另有要求时取值不同，以 ESI 为准。

    关联：u6-l1 把这些调用放进完整的主站周期任务；u6-l2 看从站固件的 SYNC0 中断；u7-l2 的"间歇性 0x001A"案例用到本课。

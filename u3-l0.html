CoE 与对象字典：从站的参数表与数据模型

EtherCAT 只管运输，运什么由 CoE 规定。SDO 和 PDO 读写的不是 ESC 寄存器，而是从站固件里的一张表：按"16 位索引 + 8 位子索引"编号的对象字典。本课先认这张表的分区和条目格式，再看两条路（邮箱 SDO、周期 PDO）怎样访问同一张表。

定位

本课目标

  1. 说出 CoE 在协议栈里的位置：EtherCAT 只提供邮箱和过程数据两种运输，CoE 借用 CANopen（CiA 301）规定数据模型、参数访问、PDO 映射、SDO Info 和 Emergency。
  2. 说出对象字典是什么：从站固件维护的、按 16 位索引 + 8 位子索引编号的参数与数据表，是 SDO 与 PDO 共同的数据源，和 ESC 寄存器（物理内存 0x0000–0x0FFF）不是一回事。
  3. 分清索引分区：数据类型区、0x1000 通信区、0x2000 厂商区、0x6000 设备行规区（CiA 402 占 0x6000–0x67FF）、0xA000 起保留区。
  4. 读懂一条对象的属性：索引、子索引、名称、对象类型（VAR 7 / ARRAY 8 / RECORD 9）、数据类型编码、访问权限、PDO 可映射性、默认值、范围、单位；知道 ARRAY/RECORD 的子索引 0 是元素个数。
  5. 说出主站从哪里知道这张表：ESI 的 <Objects>、从站在线提供的 SDO Info 服务、固件里的对象定义表，三者必须一致。
  6. 理解"同一对象、两条路"：已映射进 RxPDO 的对象每周期被过程数据覆盖，SDO 写它会被冲掉；TxPDO 对象 SDO 读到的是同一份值。

    机制拆解

    CoE 在栈里的位置

    EtherCAT 数据链路层只提供两种运输：按需的邮箱（SM0/SM1）和每周期的过程数据（SM2/SM3），它不关心里面装的是什么。CoE（ETG.1000.6）把 CANopen 应用层（CiA 301）整套搬进来，规定装什么、怎么编号；CiA 402 再在这张表的 0x6000 区定义驱动器对象。

    CoE 规定的内容走哪种运输本课程在哪讲
    数据模型：对象字典表在从站固件里，下面几项都访问它本课
    参数访问：SDO 上传/下载邮箱u3-l2
    周期数据打包：PDO 映射（0x1600/0x1A00、0x1C12/0x1C13）过程数据；映射本身在 PREOP 用 SDO 配u3-l3
    自报表结构：SDO Info邮箱本课
    主动报错：Emergency邮箱（从站主动放进 SM1，主站读邮箱时取回）u3-l2 讲报文格式

    编号与分区

    每个对象由 16 位索引定位，复合对象再用 8 位子索引选成员，写作 0x1018:01。索引空间按用途切成几段，看到索引就知道它归谁管（CiA 301 规定，CoE 原样沿用）。

    索引范围分区例子
    0x0000–0x0FFF数据类型区（0x0001–0x025F 用于类型定义，其余保留）0x0006 即 UINT16 的定义；0x0007 即 UINT32
    0x1000–0x1FFF通信区：设备身份、PDO 映射与分配、SM 参数0x1018 身份；0x1C12 SM2 PDO 分配
    0x2000–0x5FFF厂商区：各家自定义参数（增益、报警阈值……）含义完全因厂商而异，只能查该设备的手册或 ESI
    0x6000–0x9FFF设备行规区；CiA 402 驱动器第一个轴占 0x6000–0x67FF0x6040 控制字；0x607A 目标位置
    0xA000–0xFFFFCiA 301 中为保留/其他用途；EtherCAT 的模块化设备行规（ETG.5001）使用 0xF000 起的一段0xF000 模块化设备描述；普通单轴驱动器一般不涉及
    0x1018 身份对象要和 SII 对得上：:01 厂商号、:02 产品码、:03 版本号、:04 序列号，分别对应 SII 字地址 0x0008、0x000A、0x000C、0x000E（见 u2-l4）。主站按 SII 认设备、按对象字典配参数，两边不一致就会出现"认对了人、配错了参数"。

    一条对象长什么样

    对象字典的每一项都带一组属性。数据类型用 16 位编码表示，编码本身就是数据类型区里的索引。VAR 只有子索引 0；ARRAY 和 RECORD 的子索引 0 是 UINT8 的"最大子索引"，实际成员从 1 开始。

      主站怎么知道这张表

      表的"真身"是从站固件里的对象定义数组；ESI 的 <Objects>/<DataTypes> 是厂商随设备给的离线副本，SDO Info 服务是固件在线报告自己实现了什么。三者必须一致；ESI 里写了而固件没实现的对象，一访问就是 abort 0x06020000。

      SDO Info 服务（ETG.1000.6）OpCode 请求 / 应答主站得到什么
      Get OD List0x01 / 0x02索引列表（可选全部、仅 RxPDO 可映射、仅 TxPDO 可映射等）
      Get Object Description0x03 / 0x04某索引的数据类型、最大子索引、对象类型、名称
      Get Entry Description0x05 / 0x06某子索引的数据类型、位长、按 ESM 状态的读写权限、PDO 可映射性、名称（可选单位、默认值、最小/最大值）

      两条路，一张表

      SDO 是按需的一问一答，PDO 是每个周期固定搬运；两者最后都读写同一个对象。已映射进 RxPDO 的对象，表里的值每周期被主站过程数据覆盖，所以 SDO 写它只能活到下一周期；TxPDO 对象则相反，SDO 读和 PDO 读拿到的是同一份值。

      行规对象的数值带单位，单位由换算对象决定；写目标位置前要先知道"1 个位置单位是多少"。

      对象作用换算
      0x6091 齿轮比电机转数 : 轴转数:01 / :02
      0x6092 进给常数每轴转对应多少位置单位:01 / :02
      0x6065 跟随误差窗口允许的位置偏差位置单位，经上面两项换算成电机增量；未配置换算时很多驱动器的位置单位就是编码器增量，因厂商而异
      0x60C2 插补周期CSP/IP 下两点之间的时间:01 × 10^:02 秒，应等于总线周期

      主从对照

      主站做什么

      • 读 ESI 的 <Objects>，或在线用 SDO Info 把从站的对象字典读上来，认识这张表。
      • 在 PREOP 用 SDO 下载参数：运行模式、斜坡、换算系数、PDO 映射与分配。
      • 只把"PDO 可映射"的对象装进 RxPDO/TxPDO，进入 OP 后每周期通过过程映像读写它们。
      • 需要掉电保持时写 0x1010；不要用 SDO 去写已映射进 RxPDO 的对象。

      从站做什么

      • 固件持有对象字典：一张 RAM 里的对象描述数组，每项指向变量或回调。
      • 每次 SDO 访问先校验：对象/子索引存在、访问权限、当前 ESM 状态、数据长度与取值范围；不通过就回 abort code。
      • 执行回调：写 6060 触发模式切换并更新 6061；PDO 映射写完后校验并算出 SM 长度。
      • 收到 0x1010 的 "save" 签名时把参数存进 NVRAM，上电再装回表里。

      在真机上看

      从站需在 PREOP 或更高。IgH 命令行里数字按 C 语言规则解析：0x 开头是十六进制，不带前缀是十进制，所以索引一定要写 0x。

      # 看整张对象字典（需从站支持 SDO Info）
ethercat sdos -p0
# 厂商号，应与 ethercat slaves -v 的 Vendor Id 一致
ethercat upload -p0 0x1018 1 --type uint32
# 设备名（字符串）
ethercat upload -p0 0x1008 0 --type string
# 第 1 个 RxPDO 映射的条目数
ethercat upload -p0 0x1600 0 --type uint8
# 写运行模式 CSP，再读回显示值
ethercat download -p0 0x6060 0 8 --type int8
ethercat upload -p0 0x6061 0 --type int8
      命令期望说明
      sdos -p0每个对象一行 SDO 标题 + 若干子索引行空列表说明从站不支持 SDO Info 或主站没读到；输出格式以所装版本为准
      upload 0x1018 1厂商号（十六进制 + 十进制）与 slaves -v 和 SII 一致；不一致就是 u2-l4 的身份不匹配
      upload 0x1008 0设备名字符串内容因厂商而异
      upload 0x1600 0当前映射条目数，如 0x02 2与 ethercat pdos 里该 PDO 的条目数一致
      download 0x6060 0 8无输出成功静默；不支持 CSP 时打印 abort code
      upload 0x6061 00x08 8有的驱动器要在特定 CiA 402 状态才切换，回读值更新时机因厂商而异

      自测

      误区与关联

      • 误区：对象字典就是 ESC 的寄存器，0x6041 是某个内存地址。
        实际上：ESC 寄存器是芯片里 0x0000–0x0FFF 的物理内存，用 FPRD/FPWR 直接读写；对象字典是固件里的软件表，只能经邮箱 SDO 或 PDO 映射间接访问。
      • 误区：ethercat upload -p0 6041 0 读的就是状态字。
        实际上：IgH 命令行里不带前缀的数是十进制，6041 会被当作 0x1799。索引要写 0x6041；子索引写 1 或 0x01 等价，但 10 是十进制 10（0x0A），而 sdos 输出里子索引是按十六进制显示的。
      • 误区：ESI 里列出的对象，从站一定都实现了。
        实际上：ESI 可能对应别的固件版本，或列了可选对象；以 SDO Info（ethercat sdos）和实际访问结果为准，没实现的对象会回 abort 0x06020000。

      对象字典是 CANopen（CiA 301）的概念，EtherCAT 通过 CoE（CANopen over EtherCAT）整套借用，所以索引分区、数据类型编码、对象类型、SDO 与 abort code 的规则都按 CiA 301 理解；CiA 402 的 0x6000 区对象也原样适用。

      关联：下一课 u3-l1 讲 ESM 状态机（哪个状态能访问这张表）；u3-l2 讲怎么用 SDO 逐字节访问这张表；u3-l3 讲怎么把表里的对象装进周期帧。
